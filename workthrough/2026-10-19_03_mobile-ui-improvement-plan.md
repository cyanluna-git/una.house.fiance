# 모바일 UI 개선 계획

근거: 2026-10-19 실측 점검 (Playwright, 테스트 DB 복사본, 14개 화면 × 360/390/820px + 844×390 가로).
화면 전체 가로 넘침은 0건. 깨짐은 아래 원인에 몰려 있음.

## 0. 원칙

- 기준 폭 (결정 반영): 폰 `< md`(768) / 태블릿 `md`(768~1023, 좁은 사이드바) / 데스크톱 `lg`(≥1024). 입력칸 16px 규칙은 1023px 이하 전체.
- 페이지마다 직접 고치지 않고, **공통 부품/토큰으로 한 번에** 고친다. 페이지는 그 부품으로 교체만.
- 단계마다 배포 → 폰 확인 → 다음 단계. 자동 점검(3단계)이 생기기 전까지는 같은 점검 스크립트로 전후 비교.
- 기능·데이터·API 변경 없음. UI만.

## 2단계 — 공통 부품 정리 (1~2일, 화면별 커밋)

문제의 근본 원인: 페이지 파일이 크고(대출 1,115줄, 거래 833줄, 카드 665줄) 화면마다 표·카드·폼을 직접 만들어 반응형 처리가 제각각.

### 만들 부품 (`src/components/ui/`)

- `Money` (1단계에서 생성): 금액 표시 단일화
- `StatCard` / `StatGrid`: 요약 숫자 카드. 폰 2열, 데스크톱 4열 고정 규칙
- `ResponsiveList`: 같은 데이터로 **데스크톱은 표, 폰은 카드 목록**. 열 정의 하나에 `mobile: "title" | "sub" | "amount" | "hidden"` 역할 지정
- `StickyActionBar`: 하단 고정 버튼 (하단 메뉴 위, `--bottom-nav-h` 사용). 수동 입력·빠른 입력 공용
- `Modal` 개선: 폰에서는 하단 시트(전체 폭, `max-h-[90dvh]`, 안전 영역 패딩), 데스크톱은 기존 중앙 모달
- `FormField` 입력 크기 통일: 높이 44px, 폰 16px

### 교체 순서 (사용 빈도 순)

1. 거래 내역 (`transactions`) — 표 → 폰 카드 목록, 인라인 편집은 하단 시트
2. 대시보드 (`/`) — 요약 카드, 최근 거래 표
3. 수입 (`income`) — 급여 명세 카드
4. 대출 (`loans`) — 가장 큰 파일, 표 + 폼. 이참에 부분 컴포넌트로 분리
5. 나머지 (카드, 여행, 카테고리 규칙, 고정지출, 분석) — 부품 교체만

각 화면: 교체 → 360/820 스크린샷 전후 비교 → 커밋. 한 화면씩 배포 가능.

### 함께 정리

- 글자 크기 최소값: 본문 14px, 보조 12px. `text-[10px]`/`text-[11px]` 6곳 제거 (하단 메뉴 라벨 포함 → 12px)
- 탭 영역 최소 44×44
- 차트(recharts): 폰에서 높이 고정 + 범례 아래로, 축 라벨 축약

## 2단계 결과 (2026-10-20)

화면별 수정 (UI만, 기능·API·데이터 변경 없음):

- 기준 정리: 768~1023px(아이패드)는 좁은 사이드바 + 폰형 본문. 거래 내역·대시보드의 카드/표 전환 기준을 `md` → `lg`로 맞춤 (아이패드 세로에서 9열 표가 좁게 꺾이던 문제)
- 거래 내역: 필터 `sm:2열 / lg:5열`, 편집·삭제·일괄 버튼 터치 높이 40~44px, 페이지 버튼 줄바꿈 금지
- 카테고리 규칙: 폰·태블릿은 카드 목록(키워드, 분류, 우선순위, 편집/삭제 44px 버튼), 데스크톱만 표. 입력 폼 `sm:2열 / lg:5열`
- 카드: 폰에서 카드명 말줄임, 사용금액은 아래 줄로 (고정 폭 140px 제거)
- 금액: 대시보드·대출·고정지출·여행·수입·카드의 JSX 금액 표기를 `Money`로 통일 (표기 동일, 줄바꿈 금지). 차트 툴팁 등 문자열 템플릿은 그대로
- 전역: 표 머리글 `th` 줄바꿈 금지
